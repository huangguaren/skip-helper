# 李跳跳 2.2（派大星）APK 静态解包报告

样本：`tools/ltt-apk/litiaotiao.apk`
- 包名 `hello.litiaotiao.app`，versionName `派大星2.2`，versionCode `3`
- minSdk 24 / targetSdk 33，仅 arm64-v8a，3,205,494 字节
- SHA-256 `095B70EB8A186E56B01BC4951C077FF2527E1DC94BB7E54B43671A8F8F33762F`

> 根目录的 `李跳跳跳过广告.apk.1.1` 与本样本 SHA-256 完全一致（3,205,494 字节同一文件），
> 所以后续所有结论对它同样成立，不再单独解包。

## 1. 加固识别

| 证据 | 值 |
| --- | --- |
| `lib/arm64-v8a/libshell-super.2019.so` | 292,312 字节，含 `%s/files/prodexdir/oat/arm64/%s`、`libshell-superx.2019.so` |
| `lib/arm64-v8a/libshella-4.2.0.10.so` | 6,004 字节 |
| `assets/0OO00l111l1l` | 784,880 字节，文件头 `01 00 00 00 DE AD F2 E4`（非 dex，非 zip） |
| `assets/t86`、`assets/tarm` | 32 位 ELF，`7F 45 4C 46 01 01 01` |
| `classes.dex` | 63,644 字节，仅壳的入口（`MyWrapperProxyApplication` → `WrapperProxyApplication` → `Util.PrepareSecurefiles` → `System.loadLibrary("shell-super.2019")`） |

结论：**腾讯乐固（Legu）"超级壳"**。真实 dex 以 `assets/0OO00l111l1l` 形式存放，由 `libshell-super`
在运行时解密并释放到 `/data/data/hello.litiaotiao.app/files/prodexdir/` 再由壳加载。

### 静态为什么还原不出 dex

- 解密算法和密钥都在 arm64 原生库里，且与壳的初始化状态（SO 段校验、`prodexdir` 目录、odex 生成）耦合；
- 壳会在 `PrepareSecurefiles` 阶段校验自身文件，脱壳要在真机/模拟器上跑起来（Frida / BlackDex / 内存 dump）；
- 本机没有可用的 Android 设备（`adb devices` 为空），也没有 KVM 起模拟器，因此**没有做动态脱壳**。

### 载荷能不能纯静态解开：本轮实测数据

脚本 `analyze_payload.py`（同目录）对 `assets/0OO00l111l1l`（784,880 字节）做了熵与结构扫描：

| 观测 | 值 | 含义 |
| --- | --- | --- |
| 整体熵 | 7.972 | 接近均匀分布，压缩或加密 |
| 分块熵 @0x00000 → 0x30000 | 7.589 → 7.891 | 前段仍有残余结构（头表 + 索引） |
| 分块熵 @0x40000 以后 | 7.944 ~ 7.997 | 已无统计特征 |
| `dex\n` 出现次数 | 1（偏移 0x23） | 只有一处，且后面跟着 `0xff` 再 `035\0`，不是可用的 dex 头 |
| `PK\x03\x04` / `\x7fELF` | 0 | 没有内嵌 zip 或 so |
| `de\xad\xf2\xe4` | 1（偏移 0x04） | 乐固自己的容器标记 |
| 单字节异或扫描（前 64 字节窗口） | 无 key 能把头部还原成 `dex\n` | 不是单字节异或 |

结论：载荷是「头表 + 逐 dex 加密封装」的容器，密钥与算法在 `libshell-super.2019.so` 里，
静态还原需要逆向那 292 KB 的 arm64 库并复现其密钥派生——这已经超出「复刻一个跳过助手」的收益边界。
要继续只能走动态：真机/模拟器 + Frida/BlackDex 拿到内存里的 dex。

### 换了一条路拿到等价信息

**这份复刻工程的出处（2026-11-12 核实）**：

| git 远端 | `git@github.com:huangguaren/LiTiaotiao-Replica.git` |

它与工程 `dist/` 里那三个 APK 的哈希都不同，说明是该项目更早的一次构建，具体 commit 未记录。
与官方包的区别是硬指标：官方 `李跳跳2.2正式版.apk` 是 3,205,494 字节 /
`095B70EB…` / versionName `派大星2.2` / versionCode 3。

`tools/ltt-apk/jadx-out` 是本地反编译产物：`DecompileAll.java` + `jadx-headless-mcp-0.7.1-all.jar`，
2026-11-12 12:00 跑出；源码树是 `hello.litiaotiao.app`，含 `RuleDetailActivity` /
`ImportActivity` / `SettingsActivity` / `data.Repository` 这些**原版没有的类**，
进一步证明反编译对象是复刻 APK 而非官方包。

**措辞修正**：下面表格里的「原版行为」是**复刻者的还原实现**（依据原版资源字符串、布局与社区规则），
不是从官方 dex 里读出来的——官方包被乐固加固，真实 dex 静态解不出（见上一节）。
所以正确的说法是：原版**资源层**证据 + 复刻**实现层**参考，两者互证；复刻工程本身不能当官方行为证据。

## 2. 静态可读的部分（原 APK）

### 组件

| 组件 | 作用 |
| --- | --- |
| `LauncherActivity` / `MainActivity` | 首页（开关 + 更多 + 一键反馈） |
| `AppsActivity` | 应用列表 |
| `AppSettingActivity` | 单应用设置：应用开关、手势点击、圆形倒计时、青少年弹窗、新增规则 |
| `MoreActivity` | 分享、设置、百宝袋入口 |
| `TreasureBagActivity` | 哆啦百宝袋（附加工具列表） |
| `WeChatActivity` | 反馈二维码页 |
| `MyBroadcastReceiver` | `BOOT_COMPLETED` |
| `LttService` | 无障碍服务，label `♥李跳跳2.2` |

权限：`QUERY_ALL_PACKAGES`、`FOREGROUND_SERVICE`、`POST_NOTIFICATIONS`。

### 无障碍配置（`res/xml/accessibility_service_config.xml`）

```xml
android:accessibilityEventTypes="typeAllMask"
android:accessibilityFeedbackType="feedbackGeneric"
android:notificationTimeout="100"
android:accessibilityFlags="flagDefault"
android:canRetrieveWindowContent="true"
android:canPerformGestures="true"
android:settingsActivity="hello.litiaotiao.app.MainActivity"
```

注意原版**没有**开 `flagRetrieveInteractiveWindows`。SkipHelper 开了它是为了拿悬浮窗形式的广告，
是刻意的差异（见 ltt-clone/README）。

### 白名单（`res/values/arrays.xml` → `string-array name="whitelist"`）

108 个包名，覆盖相机、时钟、通讯录、文件管理、相册、录音、安全中心，以及
`com.eg.android.AlipayGphone`（支付宝）、`com.netflix.mediaclient`、`com.spotify.music` 等。
语义是"这些应用完全不接管"。

已整表移植到 `RuleStore.DEFAULT_WHITELIST`（108 条，逐条核对，见 0.5.0 的实现）。
本轮用 `verify_whitelist.py` 做了机器复核：`original=108 clone=108 missing=[] extra=[]`。

### 配置键名（`res/values/strings.xml`）

`is_main_switch_on`、`hide_toast`、`filter_invisible_nodes`、`filter_collection_nodes`、
`filter_default`、`filter_young_popups`、`click_way`、`click_way_popup`、`click_times`、`clicks`、
`delay`、`delay_popup`、`adjust_search_times_popup`、`unite_popup_rules`、`reverse_traversal`、
`keywords`、`keywords_append`、`ltt_service`、`foreground_service`、`exclude_from_recents`、
`is_user_check`、`big_smart_pg`。

其中 `adjust_search_times_popup` 的字符串值被写成 `unite_popup_rules`、`FEEDBACK_GENERIC` 的值被写成
`volume_mode` —— 这类"键名与值串位"是原版资源里的既有现象，不影响规则语义。

本轮补全的键（0.6.0 对照用）：`node_whitelist`、`max_text_length`、`max_desc_length`、`timeout`、
`try_times`、`task_type`、`texts_task2`、`show_all_apps`、`was_on_service_connected`、
`foreground_service_message`、`toast_text`、`DOCC`、`IGNORE_TYPE_VIEW_CLICKED`、
`ltt_changelog_a` / `ltt_tips_a` / `ltt_suggestions_a`、`app_version_name`。

其中 `max_text_length` / `max_desc_length` 说明原版收集节点文本时会截断（控制遍历开销），
`node_whitelist` 是「这些节点永不点击」的二级过滤，`timeout` / `try_times` / `task_type` / `texts_task2`
属于「百宝袋」里的任务型脚本参数，与开屏跳过主链路无关。

### 规则弹窗（`res/layout/rule_input_dialog.xml`）

两个输入框 + 一个勾选：

- `et_id` hint「用来定位弹窗的文字、id、\nbounds」
- `et_action` hint「用来关闭弹窗的文字、id、\nbounds」
- `ctv_back`「能否通过返回键关闭」

说明原版的 `id` 字段本身就可以写 `bounds`（坐标触发器），不只是文字/资源 id。SkipHelper 的匹配器目前
只按 text/desc/resId 匹配，坐标触发这一形态还没支持——已记入 0.5.0 的已知差异。

## 4. 复现命令

```powershell
# 静态解码（资源、清单、smali 壳入口、assets）
tools\android\apktool.cmd d tools\ltt-apk\litiaotiao.apk -o tools\ltt-apk\unpacked -f

# 载荷可解性判定（熵 / 魔数 / 单字节异或扫描）
& $PY tools\ltt-apk\analyze_payload.py

# 查看白名单
Select-String tools\ltt-apk\unpacked\res\values\arrays.xml -Pattern 'whitelist' -Context 0,120

# 提取配置键名
Select-String tools\ltt-apk\unpacked\res\values\strings.xml -Pattern 'ltt_|delay|filter_|click_'
```

动态脱壳（需要真机/模拟器，本机未执行）：

```bash
# 设备上跑起来后 dump 内存里的 dex
frida -U -f hello.litiaotiao.app -l dexdump.js --no-pause
# 或 BlackDex / youpk 之类在设备端脱壳，产物在 /sdcard/Android/data/.../dex/
```
